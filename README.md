# HaloBattery 中文版 · 迈从 2.4G 键鼠电量支持

给 [HeyOkay/HaloBattery](https://github.com/HeyOkay/HaloBattery) 补上两件上游没有的东西：

- **迈从（MCHOSE）2.4G 无线键鼠的电量读取**：键盘 G75、鼠标 G3 实测通过
- **完整简体中文界面**：托盘菜单、偏好设置、设备标签、通知、诊断文案

上游是 MIT 许可的 Windows 托盘小工具，原本能显示蓝牙耳机、雷蛇、罗技等设备的电量，但对这套国产 2.4G 接收器完全无感。这个仓库记录了我们把它读出来所用的协议、代码和验证过程。

## 为什么不能只"加个 VID"

最直觉的做法是把 `0x258a`、`0x3554` 加进上游的 MchoseProvider 白名单，但那行不通：上游用的是 RealTek `0x06` 指令 + 21/65 字节 feature report，而这两颗芯片根本不认这套帧。

真正卡住的地方有两个，都是**通道选错**：

- 键盘接收器 `3554:fa09` 的控制集合声明 `Input 20 字节 / Output 20 字节 / Feature 0 字节`。前五轮探针一直在发 feature report，等于对着一扇不存在的门敲。
- 鼠标接收器 `258a:0138` 的 `0x09` 是**命令/数据共用的缓冲区**：不先发命令就直接读，健康唤醒的鼠标也一律返回 `read error`。

结论来自读取设备自身的 HID 能力（`HidD_GetPreparsedData` + `HidP_GetCaps`），不是猜 report ID。Windows 上 `IOCTL_HID_GET_REPORT_DESCRIPTOR` 会返回 `ERROR_INVALID_FUNCTION`，别走那条路。

## 协议速览

**键盘 · Compx `3554:fa09` → `providers/compx.py`**

控制集合 `usage_page = 0xFF02`，走 **output report `0x13`**，20 字节双向帧：

```
[0] 0x13   [1] 命令   [2] 子命令   [3] 分片号
[4..18] 负载(15 字节)   [19] sum(frame[0:19]) & 0xFF
```

- 查询电量：`13 4A 01 00` + 15×`00` + `58`
- 回应：`13 4A 01 00 02 <电量> <状态> ...` → 电量在 **byte 5**
- 查在线：`0x07`，回应的 byte 5 为 `1` 在线 / `0` 关机
- 同通道还能读配置块：`0x44` RGB（10 片）、`0x41` 宏（36 片）、`0x42` 键映射（27 片）、`0x43`（37 片）、`0x49` 调色板（35 片）

**鼠标 · SINO WEALTH `258a:0138` → `providers/sino.py`**

控制集合 `usage_page = 0xFF02`，走 **feature report `0x09`**，520 字节：

```
发送：09 0C 09 00 + 516 个 00
回应：09 0C 09 00 00 00 00 00 <电量>      (9 字节，电量在 byte 8)
```

**每次轮询都必须重新发命令**。这个 feature 不是可直接读的寄存器，任何别的命令（比如读灯光配置的 `09 6E 44 00`）都会把缓冲区覆盖掉。

鼠标命令帧的形状来自迈从官方驱动 `MCHOSE HUB` 留下的两个文件：`C:\MCHOSE\Log.txt`（记录它全部 HID 收发）和 `Products\G3\G3_data.ini`（`Keys="09,6c,01,00,..."`、`Base="09,6e,44,00,..."`）。电量命令本身不在模板里，是对活设备穷举读类命令找到的。

## 怎么确认读数是真电量，不是固件占位值

「读到 100」本身什么也证明不了 —— 满电和写死的默认值长得一样。我们用了几条互不依赖的证据：

- **关机对照**：键盘断电后 `0x4A` 彻底不回应，而不是继续返回 100；同通道 `0x07` 的在线字节精确翻转 `1 ↔ 0`；重新开机读数恢复。占位值不会跟着设备消失。
- **本地硬件对照**：G75 按住 `Fn+B` 由键盘固件点亮电量条，满格，与软件读到的 100% 一致。这条路不经过 USB。
- **独立数据源对照**：鼠标切蓝牙后，Windows 显示 86%；同时段 2.4G 读到 84~85%。误差 1~2%。
- **时间维度（最硬的一条）**：两周后复测，未插电的键盘从 100% 掉到 **85%**，鼠标从 84% 涨到 **100%**（中间充过电）。一个降 15、一个升 16，方向相反 —— 固定值、单向计数器、缓存快照都无法解释。

## 已知限制

- 鼠标切到**蓝牙模式**时 2.4G 射频关闭，读不到；休眠时同样读不到。两种情况下图标会保留上次读数并置灰。
- 键盘关机时 `0x4A` 无回应，也是同样处理。
- 蓝牙耳机电量由上游的 Windows PnP 属性提供，部分红米耳机会恒定上报 100%，本仓库**未修复**该项。
- 协议在 G75 3.0 键盘 + G3 鼠标上验证。同芯片家族的其他型号大概率通用，但 PID 和 usage page 需要自行核对。
